Decision Reconstruction Manifest

The Decision Reconstruction Manifest describes the information a separately governed record-review artifact would need to preserve: source identity, review conditions, chronology, provenance, integrity metadata and human-review status.

Publication scope. This page is a conceptual reference for documentation traceability. It does not offer a machine-readable service, record submission, assessment output, or production artifact. No confidential records should be provided through this website.

What the Manifest does

Pins the evaluation

Documents the methodology, codebook, Manifest format, and provenance fields required to interpret a future review artifact.

Preserves the result

Defines a portable structure for five condition results, routing vocabulary, warnings, and a human-review requirement.

Supports later verification

Uses an input hash and a canonical Manifest hash so later reviewers can check correspondence and detect alteration.

Describes a future storage boundary

A future authorized implementation would require a separately approved storage, retention, and access design. JRS is not presented as a public repository for records.

Record-review information model

A reconstructable review record would identify the reviewed material, the applicable method, the evidence considered, the disposition of each condition, and the responsible human reviewer. This description is not a report of an operational deployment or a public assessment service.

Minimum field groups

GroupPurpose
manifest_id, created_atIdentifies the artifact and creation time.
manifest_version, jrs_version, codebook_versionKeeps the artifact, methodology, and rule versions distinct.
inputRecords the input hash, algorithm, length, and truncation state without requiring the underlying record to be embedded.
condition_vocabulary, conditionsDeclares which condition-key vocabulary is used and records all five results.
routingRecords both the routing value and the vocabulary used to interpret it.
human_reviewStates that human review is required and gives the reason.
content_classDeclares whether the artifact contains no record content, derived record content, or the record itself.
integrityRecords the canonicalization method, Manifest hash, and optional signature metadata.

Integrity and hashing

The input hash allows a holder of the original record to test whether it corresponds to the evaluated input. The Manifest hash is computed over the canonical form of the artifact, excluding the integrity object itself. A changed routing result, version, condition, or input hash therefore changes the Manifest hash.

Important limit. Hash consistency is not authentication. An unsigned Manifest can be checked for internal consistency, but it does not prove who created it. A digital signature and governed key-custody process are required before authenticity can be claimed.

Human review requirement

Version 1.0 requires human_review.required. The Manifest format is not validated for autonomous consequential-decision use. A Manifest records a documentation evaluation. It does not decide whether the underlying decision is correct, lawful, compliant, or professionally justified.

Future storage boundary

The specification is designed so that a future authorized implementation could preserve evidence-artifact information without making JRS a public repository for the underlying record. No such implementation, data flow, retention practice, or integration is authorized or represented as available on this site.

Limitations

No legal conclusion

The Manifest does not establish admissibility, legal sufficiency, compliance, certification, or defensibility in law.

No autonomous decision

The Manifest preserves a review result. The responsible human or organization retains authority over the consequential decision.

Derived content may remain sensitive

Condition notes and remediation text can paraphrase the evaluated record. The content class must identify that risk.

Vocabulary remains explicit

Review-condition terminology must be explicitly identified and kept consistent with the publication actually applied. Unverified mappings must not be treated as authoritative.
