Decision Reconstruction Manifest

The Manifest is a portable, machine-readable specification for documenting one JRS evaluation. It defines the version, vocabulary, integrity metadata, and human-review status that a future artifact would need to preserve.

Current status. The Manifest 1.0 schema revision 1.0.1 and a controlled implementation library exist and have passed repository conformance and integrity tests. No public API accepts record text, returns a Manifest, or provides a Manifest-generation service. The specification is public. Controlled implementation and evaluation materials remain non-public. The Engine remains unvalidated.

Schema revision 1.0.1. The Manifest format remains 1.0. The current schema accepts JRS Standard 1.0 and Codebook 1.0 and rejects unsupported identifiers. The earlier v1.0 schema remains available for historical interpretation. A valid hash demonstrates internal consistency, not that a claimed version exists or that an unsigned artifact is authentic.

What the Manifest does

Pins the evaluation

Defines fields for the JRS, Codebook, engine, model, API, and Manifest versions used in a future evaluation.

Preserves the result

Defines a portable structure for five condition results, routing vocabulary, warnings, and a human-review requirement.

Supports later verification

Uses an input hash and a canonical Manifest hash so later reviewers can check correspondence and detect alteration.

Describes a future storage boundary

A future authorized implementation would require a separately approved storage, retention, and access design. JRS is not presented as a public repository for records.

Integrity and hashing

The input hash allows a holder of the original record to test whether it corresponds to the evaluated input. The Manifest hash is computed over the canonical form of the artifact, excluding the integrity object itself. A changed routing result, version, condition, or input hash therefore changes the Manifest hash.

Important limit. Hash consistency is not authentication. An unsigned Manifest can be checked for internal consistency, but it does not prove who created it. A digital signature and governed key-custody process are required before authenticity can be claimed.

Human review requirement

Version 1.0 requires human_review.required. The present engine is not established as validated for autonomous consequential-decision use. A Manifest records a documentation evaluation. It does not decide whether the underlying decision is correct, lawful, compliant, or professionally justified.

Future storage boundary

The specification is designed so that a future authorized implementation could preserve evidence-artifact information without making JRS a public repository for the underlying record. No such implementation, data flow, retention practice, or integration is authorized or represented as available on this site.

Limitations

No legal conclusion

The Manifest does not establish admissibility, legal sufficiency, compliance, certification, or defensibility in law.

No autonomous decision

The Manifest preserves a review result. The responsible human or organization retains authority over the consequential decision.

Derived content may remain sensitive

Condition notes and remediation text can paraphrase the evaluated record. The content class must identify that risk.

Vocabulary remains explicit

The schema does not silently relabel Review Engine keys as Codebook conditions. Any mapping must be documented and versioned.

Publication boundary

Publication permits inspection of the schema. It does not grant source-code, implementation, derivative, trademark, commercial embedding, exclusivity, or transfer rights. It also does not authorize use of the controlled Engine or submission of records to this website.
